# 市场简报

## 用途

市场简报把每天的市场研究拆成前后呼应的两个时点：

- **08:00 盘前**：汇总北京时间 08:00 前最重要的 8 条资讯，梳理隔夜指数、商品、汇率与政策，明确核心矛盾、影响板块和开盘后要验证的变量。周末和休市日也生成。
- **19:15 收盘**：在 18:30 本地行情更新之后，核对指数、成交额、涨跌家数、申万板块和大小盘/成长价值风格；同时列出当日最重要的 8 条资讯，逐条分析“资讯—传导逻辑—盘面证据—归因结论”，并复盘晨间判断。

页面地址：<http://127.0.0.1:8765/market_brief.html>。原始资讯时间轴仍在
<http://127.0.0.1:8765/market_news.html>，两页互相跳转：资讯页回答“当时发生了什么”，简报页回答“这些事实如何影响市场情境，以及后来是否得到验证”。

简报选取重要资讯时应优先读取资讯中心的事件聚合结果，而不是按平台简单拼接。每条入选
资讯建议保存 `event_id`、`verification_label` 与来源平台；页面会提供“查看来源链”入口。
同一事件被五个平台转载仍只占一个重要资讯席位。晨报只允许使用 08:00 前可见的来源链，
收盘简报再补充当天新增的官方确认和交叉报道，并用于解释晨间判断为何成立或失效。

## 数据与修订

简报永久保存在 `state/market_briefs.sqlite3`。同一日期、同一类型重复发布完全相同的内容不会新增记录；内容发生变化时增加修订版本，页面默认读取最新版本并保留修订清单。

状态分为：

- `complete`：本期所需数据完整；
- `partial`：已保存可用快照，但本地行情或部分来源尚未齐全；
- `generating`：正在生成；
- `failed`：本期生成失败，旧的成功版本不会被覆盖。

页面只读取 SQLite 预计算结果，打开页面不会扫描全市场 Parquet，也不会触发资讯抓取。

## 手工发布与补跑

发布命令只接受 JSON 文件或标准输入：

```bash
python -m scripts.reports.publish_market_brief --kind morning --input /tmp/morning.json
python -m scripts.reports.publish_market_brief --kind close_style --input /tmp/close-style.json
```

先校验、不写入：

```bash
python -m scripts.reports.publish_market_brief --kind morning --input /tmp/morning.json --check
```

允许的来源链接仅限 `http` 和 `https`；页面对正文和标题统一转义，不执行简报中的 HTML、脚本、SQL 或文件路径。

## 只读接口

```text
GET /api/market-brief/dates
GET /api/market-brief/day?date=YYYY-MM-DD
GET /api/market-brief/latest?kind=morning|close_style
```

这些接口只读。写入只允许本机发布命令执行，没有面向网页开放的 POST 接口。

## 自动任务与失败边界

Codex 本地任务分别在每天 08:00 和工作日 19:15 运行。完整简报必须含 8 条重要资讯；若可信来源不足 8 条，应发布 `partial` 并说明缺口，不能用低质量或重复资讯凑数。收盘任务会先检查本地更新状态：若当天行情尚未完整，就发布 `partial` 快照并明确列出缺失项，不会把旧行情伪装成当天数据。任务失败不影响行情更新、选股仪表盘、观察池和市场资讯页。

收盘归因不是简单把新闻和涨跌并排展示。每条原因都必须包含：已确认的资讯事实、合理的传导机制、当天可观察的价格/成交/板块证据，以及“证据较强、部分解释、不支持”之一。没有盘面证据时只能列为待验证，不能把时间上的先后关系直接写成因果关系。

晨间判断复盘不只写“对/错”，还要保留盘面证据、偏差来源和次日修正，使每天的预测能够被追溯、被证伪并逐步迭代。

简报中的红色表示上涨或偏多，绿色表示下跌或偏空，蓝色表示中性选择。新闻事实、模型判断和待验证条件使用不同区块，避免把推断写成已确认事实。所有简报仅用于研究与复盘，不构成投资建议。


## 规则保底自动生成

大模型不可用时，仍可用本地资讯库 + 市场情境自动出稿：

```bash
# 先礼貌拉资讯（可选）
python -m scripts.reports.fetch_market_news --source all --date 2026-09-24

# 晨报 / 收盘风格（校验）
python -m scripts.reports.generate_market_brief --kind morning --date 2026-09-24 --check
python -m scripts.reports.generate_market_brief --kind close_style --date 2026-09-23 --check

# 发布并刷新页面
python -m scripts.reports.generate_market_brief --kind morning --date 2026-09-24
```

规则引擎会：

- 按重要性 / 交叉印证 / 来源数给事件打分，最多选 8 条；
- 不足 8 条时标记 `partial`，不硬凑；
- 拼 headline、主线风格、风险等级、观察变量；收盘稿附资讯归因与晨报复盘；
- 写入 `state/market_briefs.sqlite3` 并刷新 `output/market_brief.html`。

定时任务（Grok Bot 例程）：每天 08:00 晨报；工作日 19:15 收盘风格简报。页面：http://127.0.0.1:8765/market_brief.html

## 敏感话题与账号风险

- **保底生成不调大模型**：只读本地资讯库与行情情境，拼 JSON 写库刷新页面，不会因「写简报」触发 Codex / 对话账号封禁。
- **选材过滤**：`brief_builder.is_sensitive_event` 在入选前跳过命中敏感词的事件（政治极端表述、暴力恐怖、色情赌博诱导等）；宁可 partial，也不写入正文。
- **拉资讯另说**：多源抓取仍走限速/退避；与简报拼装解耦，不会因生成简报而加码打站。
