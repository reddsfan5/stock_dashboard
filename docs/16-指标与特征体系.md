# 16 — 指标与特征体系

## 一、为什么把指标从回测代码中拆出来

行情事实、指标公式和策略条件是三个不同层次：

```
data/       原始事实：OHLC、前收、成交量、成交额、换手率、估值快照
features/   可复算特征：均线、量比、波动、流动性、相对强弱
screen/     选股规则：组合特征并输出候选标的
backtest/   执行与验证：信号时点、成交、费用、持仓、绩效
```

这样修改公式时只改一处，选股与回测共享同一口径；数据源切换也不会迫使策略
读取供应商私有字段。

## 二、量比的三个口径

### 1. 日成交量比

`volume_ratio_20 = 当日成交量 / 前20个交易日平均成交量`

分母严格排除当日。它回答“今天成交股数相对历史是否放大”，适合量价、换手和
筹码活跃度研究。

### 2. 日成交额比

`amount_ratio_20 = 当日成交额 / 前20个交易日平均成交额`

它同时受成交量和价格影响，更适合资金容量、流动性和成交冲击研究。旧代码中的
`vol_ratio_5/20` 实际一直使用成交额；现在仅作为兼容别名保留，新策略必须使用
`amount_ratio_*` 明确表达含义。

### 3. 盘中量比

`盘中量比 = 当日截至当前分钟累计成交量 / 前5日同一时刻平均累计成交量`

不能用 09:40 的累计量直接除全天均量。分时查询页显示这个口径，至少有 3 个历史
交易日同分钟样本才给值，避免少量样本造成误导。

## 三、日频特征配置

```python
from features import compute_daily_features

# 日常选股：价格、均线、动量、成交额比、突破等
core = compute_daily_features(cache, profile="core")

# 量价/流动性：在 core 上增加成交量比、换手、VWAP
liquidity = compute_daily_features(cache, profile="liquidity")

# 研究：再增加 ATR、年化波动、下行波动、回撤、Amihud、相对强弱
research = compute_daily_features(cache, profile="research")
```

`features/catalog.py` 集中维护配置和指标元数据。新增指标时：

1. 在数据契约中确认原始字段与单位；
2. 在特征模块实现无前视公式；
3. 在目录中登记 key、分组、说明和单位；
4. 补充最小样本、分母排除当日、停牌/零成交等边界测试；
5. 最后才在选股脚本引用，不能在策略里复制一份滚动公式。

## 四、已经提供的重要指标

| 领域 | 指标 | 用途与注意点 |
|---|---|---|
| 价格 | `mom1/5/10/20/60` | 区间动量；策略信号日与成交日仍需错开 |
| 趋势 | `ma5/10/20/50/150/200` | 趋势结构，不应单独作为买卖结论 |
| 波幅 | `amp5/10/20/40`、`atr14_pct` | 网格宽度、止损距离、仓位缩放 |
| 量能 | `volume_ratio_5/20` | 成交股数相对历史；存量旧日期可能因无量字段为空 |
| 资金 | `amount_ratio_5/20` | 成交金额相对历史；可用于容量过滤 |
| 换手 | `turnover_rate`、`turnover_ma20` | 活跃度、拥挤度；单位统一为百分数 |
| 流动性 | `vwap`、`amihud_20` | 成交均价和价格冲击代理；VWAP 依赖真实成交量 |
| 风险 | `volatility_20_ann_pct`、`downside_vol_20_ann_pct` | 总波动与下行风险要分开看 |
| 回撤 | `drawdown_from_high_60_pct` | 当前价相对 60 日高点的回撤 |
| 相对强弱 | `market_relative_mom20/60` | 个股动量减当日全市场中位数，降低市场方向干扰 |
| 形态 | `near_high_*`、`breakout_*`、`overlap_pct` | 近高、放量突破和 K 线重叠 |

## 五、缓存为何不会再停在旧日期

特征缓存位于 `cache/features/<股票池>-<配置>/`。每个目录包含 manifest，记录：

- 公式版本；
- 股票池代码摘要；
- 源数据首末日期、行数和最新日覆盖数；
- 最近两个交易日 OHLC、前收、量额和换手率摘要；
- 原始字段集合和特征文件清单。

只要日线增加、股票池变化、最新行情被修订、字段升级或公式版本变化，缓存就会
自动失效并重算。不同股票池和 `core/liquidity/research` 配置互不串用。

## 六、网页决策快照与防剧透指标

`features/snapshot.py` 是选股网页的截面适配层。它只读取每只标的最近 65 个交易日，
生成每代码一行的稳定快照，再由 `scripts/screen.py` 一次性关联到所有选股结果。它不
改变各策略的入选逻辑，因此网页二次筛选与原始策略信号可以分别审计。

`features/revealed.py` 是 T+1 训练的时点适配层。历史部分仅使用模拟日前的完整日线，
当前日只使用已播放分钟合成的部分 K 线；盘中量比和 VWAP 直接取当前已揭示分钟。
这两个适配层共享指标含义，但输入边界不同，不能拿收盘决策快照直接填进历史训练页面。

网页呈现遵循“筛选 → 判断 → 风险”分层：量比、换手和成交额用于可交易性筛选；动量、
相对强弱和 VWAP 偏离用于行情判断；ATR、年化波动和回撤用于风险尺度。动态 PE、市值
等供应商快照只在有数据时显示，缺失保持空值。

## 七、下一批指标的扩展边界

以下指标有价值，但必须先接入可靠且可追溯的数据源，不能用当前行情字段伪造：

- 复权因子、除权除息和停复牌状态；
- ROE、经营现金流、营收/利润增长及财报公告日；
- 北向/主力资金等资金流（必须记录供应商口径）；
- ETF 的 IOPV、折溢价、份额和申赎；
- 行业/指数正式成分与历史权重。

接入时应新增独立事实表，通过 `代码+交易日/公告日` 关联，不把它们硬塞进日 K
主表。财务数据回测必须按公告日生效，避免使用报告期数据造成前视偏差。
