# 市场资讯复盘

## 目标

市场资讯页只解决两个问题：

1. 在模拟交易的某个时刻，当时已经公开了哪些市场级重要消息；
2. 哪一条消息实际改变了自己的观察、选股、买入、持有或卖出决定。

它不抓取每只股票的全部新闻，而是维护影响大盘、风格与板块的市场级资讯中心。当前
同花顺 7×24 由程序自动刷新；东方财富、华尔街见闻、开盘啦、韭研公社以及交易所、
监管机构等公开信息可以通过标准化导入进入同一时间轴。本地仅保存标题、摘要、发布时间、
标签和原文链接，不复制文章全文，也不依赖登录态、付费墙或未公开接口。

页面默认使用“事件聚合”视图：相似报道合成一个事件，保留每家平台的来源链。可信等级为：

| 等级 | 含义 |
|---|---|
| 官方确认 | 事件来源中包含交易所、监管机构、政府部门或公司正式公告 |
| 权威印证 | 包含已定义的权威一手来源 |
| 多源报道 | 至少两个相互独立的平台报道，但不等同于官方确认 |
| 单源报道 | 当前只有一家财经媒体记录 |
| 社区线索 | 来自社区研究，只用于发现线索，必须进一步核验 |

事件的等级与来源数量会按 `as_of` 重新计算。例如官方确认在 14:00 才发布，那么 10:15
的模拟训练仍只显示当时的“单源报道”，不会提前泄露下午的印证。

## 使用

```bash
python -m scripts.serve start news
```

浏览器打开 <http://127.0.0.1:8765/market_news.html>。页面可在“事件聚合”和“实时流”间切换，
也可按来源、时段、标签和关键词过滤。实时流分为：

| 时段 | 时间范围 | 用途 |
|---|---:|---|
| 早盘 | 00:00–09:29 | 隔夜市场、宏观政策和开盘前已知信息 |
| 午间 | 09:30–12:59 | 上午盘中快讯与午间综述 |
| 收盘 | 13:00–23:59 | 午后变化、收盘总结及盘后消息 |

日期旁的“只看截至时刻”是防剧透开关。例如选择 `2026-08-25 10:15`，服务端只会
返回发布时间不晚于 10:15 的资讯，收盘总结不会发送给浏览器。点击“查看全天”才进入
完整复盘视角。

T+1 交易训练页的“市场资讯”链接会自动附带模拟日期、当前播放时间和证券代码，因此
打开后默认就是当时可见的信息集合，而不是全天结果。

训练页面右侧同时有“模拟实时资讯”区域。每次分时向前推进后，浏览器只向服务端查询
截至新时刻可见的条目；新发布的标题和摘要会追加、高亮并自动滚动到最新一条。页面最多
保留最近 40 条可见消息，完整记录仍可从“完整时间轴”进入。全天资讯不会预先下发到
浏览器，因此暂停、单步、快速播放和直达收盘使用的是同一套防剧透边界。

## 记录消息影响

每条资讯都可以新增一条影响记录，包含：

- 关联标的，可留空表示市场整体；
- 当时决策时刻；
- 动作：观望、纳入候选、买入、持有、卖出或回避；
- 当时理解：偏利多、偏利空、中性或不确定；
- 自己的判断依据。

资讯缓存和不可再生的影响记录保存在 `state/market_news.sqlite3`。删除采用软删除，不直接
抹掉历史。资讯影响
记录与选股日记承担不同职责：前者说明“哪条公开信息改变了判断”，后者说明“对某个
标的形成了什么交易计划”。

复盘时不要把“消息发布后股价上涨”等同于“消息导致上涨”。应同时核对发布时间、价格
反应、板块联动、成交量和当时是否已经存在预期，避免事后归因。

## 缓存与历史覆盖

- 当天数据默认最多缓存 3 分钟，再次打开会自动增量刷新；也可手动点击“刷新同花顺”。
- “刷新同花顺”只刷新公开的同花顺实时流；其他平台由定时研究任务或人工校验后导入，
  页面不会把未抓取的平台伪装成已覆盖。
- 历史日期首次查询需要从公开滚动列表向前扫描，随后直接读取本地缓存。
- 每日更新管线增加了非关键 `news` 阶段，收盘后自动留存当天资讯，防止旧消息超出公开
  列表窗口。
- 公开接口可能无法覆盖很早的历史日期。页面会明确显示“窗口未覆盖”，不会伪造或用
  后来报道替代当时资讯。
- 资讯抓取失败不会阻断行情数据库更新；已有本地缓存时仍可离线复盘。

单独补存某一天可以运行：

```bash
python -m scripts.update_cache --only news --target-date 2026-08-25
```

资讯字段和用户影响记录使用 SQLite；大体量行情仍使用 Parquet，两者不会混在一个表里。

## 程序化多源抓取（礼貌限速）

东财快讯与华尔街见闻可通过公开 JSON 列表低频抓取，再写入同一资讯库；同花顺仍走原有自动刷新。

```bash
# 先 dry-run 看摘要（不写库）
python -m scripts.reports.fetch_market_news --source eastmoney --date 2026-09-24 --dry-run
python -m scripts.reports.fetch_market_news --source wallstreetcn --date 2026-09-24 --dry-run

# 校验字段后写入
python -m scripts.reports.fetch_market_news --source all --date 2026-09-24
```

安全约定（代码内强制）：

- 默认请求间隔 ≥ 1.5 秒，可用 `--min-interval` 调大，但不得低于 1.0 秒；
- 单源默认最多 8 页、20 次 HTTP；整轮不并发、不登录、不绕过付费墙；
- 遇 429/5xx 指数退避；达到上限即停止，不继续打服务器；
- 只保存标题、摘要、时间与原文链接，不复制全文。

抓取结果进入事件聚合后，可再做「无大模型保底简报」（下一步）；大模型账号异常时，采集与入库不应中断。

## 导入其他公开来源

统一导入命令只接受 JSON，不接受 SQL、脚本、任意网页 HTML 或本地文件路径作为数据字段：

```bash
python -m scripts.reports.import_market_news \
  --source eastmoney --input /tmp/eastmoney-news.json
```

支持的来源键为 `official`、`tonghuashun`、`eastmoney`、`wallstreetcn`、`kaipanla`、`jiuyan`。
每条数据至少包含 `title` 与 ISO 8601 格式的 `published_at`，建议同时提供 `digest`、`url`、
`original_source`、`tags` 和 `importance`。先校验不写入可使用 `--check`。资讯中心会自动生成
稳定编号、校验北京时间日期、过滤非 HTTP(S) 链接，并幂等更新已有记录。

训练页另有「市场情境」页签（宽基指数与海外摘要），与资讯共用同一 `as_of` 防剧透时钟，数据模块见 `data/market_context.py`。
