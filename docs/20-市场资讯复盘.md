# 市场资讯复盘

## 目标

市场资讯页只解决两个问题：

1. 在模拟交易的某个时刻，当时已经公开了哪些市场级重要消息；
2. 哪一条消息实际改变了自己的观察、选股、买入、持有或卖出决定。

它不做全网新闻聚合，也不抓取每只股票的个股新闻。默认会排除同花顺标记为“公告”的
公司公告，仅保留市场级重要消息。第一版数据源是
[同花顺财经 7×24 重要资讯](https://news.10jqka.com.cn/realtimenews.html)，本地仅保存
标题、摘要、发布时间、标签和原文链接，不复制文章全文。

## 使用

```bash
python -m scripts.serve start news
```

浏览器打开 <http://127.0.0.1:8765/market_news.html>。页面分为：

| 时段 | 时间范围 | 用途 |
|---|---:|---|
| 早盘 | 00:00–09:29 | 隔夜市场、宏观政策和开盘前已知信息 |
| 午间 | 09:30–12:59 | 上午盘中快讯与午间综述 |
| 收盘 | 13:00–23:59 | 午后变化、收盘总结及盘后消息 |

日期旁的“只看截至时刻”是防剧透开关。例如选择 `2026-08-25 10:15`，服务端只会
返回发布时间不晚于 10:15 的资讯，收盘总结不会发送给浏览器。点击“查看全天”才进入
完整复盘视角。

T+1 交易训练页的“市场资讯”链接会自动附带模拟日期、当前播放时间和证券代码，因此
打开后默认就是当时可见的信息集合，而不是全天结果。

训练页面右侧同时有“模拟实时资讯”区域。每次分时向前推进后，浏览器只向服务端查询
截至新时刻可见的条目；新发布的标题和摘要会追加、高亮并自动滚动到最新一条。页面最多
保留最近 40 条可见消息，完整记录仍可从“完整时间轴”进入。全天资讯不会预先下发到
浏览器，因此暂停、单步、快速播放和直达收盘使用的是同一套防剧透边界。

## 记录消息影响

每条资讯都可以新增一条影响记录，包含：

- 关联标的，可留空表示市场整体；
- 当时决策时刻；
- 动作：观望、纳入候选、买入、持有、卖出或回避；
- 当时理解：偏利多、偏利空、中性或不确定；
- 自己的判断依据。

资讯缓存和不可再生的影响记录保存在 `state/market_news.sqlite3`。删除采用软删除，不直接
抹掉历史。资讯影响
记录与选股日记承担不同职责：前者说明“哪条公开信息改变了判断”，后者说明“对某个
标的形成了什么交易计划”。

复盘时不要把“消息发布后股价上涨”等同于“消息导致上涨”。应同时核对发布时间、价格
反应、板块联动、成交量和当时是否已经存在预期，避免事后归因。

## 缓存与历史覆盖

- 当天数据默认最多缓存 3 分钟，再次打开会自动增量刷新；也可手动点击“刷新同花顺”。
- 历史日期首次查询需要从公开滚动列表向前扫描，随后直接读取本地缓存。
- 每日更新管线增加了非关键 `news` 阶段，收盘后自动留存当天资讯，防止旧消息超出公开
  列表窗口。
- 公开接口可能无法覆盖很早的历史日期。页面会明确显示“窗口未覆盖”，不会伪造或用
  后来报道替代当时资讯。
- 资讯抓取失败不会阻断行情数据库更新；已有本地缓存时仍可离线复盘。

单独补存某一天可以运行：

```bash
python -m scripts.update_cache --only news --target-date 2026-08-25
```

资讯字段和用户影响记录使用 SQLite；大体量行情仍使用 Parquet，两者不会混在一个表里。

训练页另有「市场情境」页签（宽基指数与海外摘要），与资讯共用同一 `as_of` 防剧透时钟，数据模块见 `data/market_context.py`。
