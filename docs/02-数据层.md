# 02 — 数据层

## 架构

```
外部源
  主源：腾讯（AkShare 历史 + qt.gtimg.cn 收盘快照）
  备源：BaoStock（增量失败子集）；新浪（首次全量重建 / 分钟备源）
  行业：申万 2021；资讯：同花顺公开 7×24
    │
    ├─ data/schema.py        字段、类型和单位契约
    ├─ data/sources.py       源适配与统一日 K 格式
    ├─ data/storage.py       Parquet/JSON 原子写入
    ├─ data/kline.py     ──→ cache/stock_kline_cache.parquet
    ├─ data/etf.py       ──→ cache/etf_kline_cache.parquet
    ├─ data/index.py     ──→ cache/index_kline_cache.parquet
    ├─ data/minute.py    ──→ cache/minute_kline_cache.parquet
    ├─ data/daily_basic.py → cache/daily_basic_cache.parquet
    ├─ data/enrichment.py    用分钟量补齐日 K 空成交量（不覆盖已有值）
    ├─ data/industry.py  ──→ cache/stock_info.parquet
    ├─ data/journal.py   ──→ state/stock_journal.sqlite3
    ├─ data/market_news.py → state/market_news.sqlite3
    ├─ data/index_minute.py → cache/index_minute_cache.parquet
    ├─ data/global_markets.py → cache/global_markets_cache.parquet
    ├─ data/market_context.py   训练页市场情境组装（as_of 截断）
    ├─ data/training_sessions.py → state/training_sessions.sqlite3
    ├─ data/calendar.py      ──→ cache/trading_calendar.parquet
    └─ data/stock_facts.py   ──→ cache/daily_limit_facts.parquet / stock_status.parquet
```

**持久化分工：** 大体量行情与特征用 **Parquet**（`cache/`）；选股日记、市场资讯与训练闭环用 **SQLite**（`state/`）。不是 MySQL/Postgres。各表通过 `代码`（如 `sh600519`；ETF 常用纯数字如 `510050`）关联。

## 一、K 线数据层 (`data/kline.py`)

### StockData 类

核心数据管理器，封装了缓存读写、增量更新、数据查询。

#### 基本使用

```python
from data.kline import StockData

data = StockData()

# 增量更新（首次全量 ~27min，后续 ~1-2min）
data.update()

# 查看概况
print(data.stock_count)      # 约 4400 只
print(data.date_range)       # (Timestamp('2024-01-02'), Timestamp('2026-08-01'))
print(data.latest_dates)     # 最近 10 个交易日
```

#### 查询 API

```python
# 单只股票 K 线
kline = data.get_kline("sh600519", days=10)
# → DataFrame: 日期, 开盘, 最高, 最低, 收盘, 前收, 成交量, 成交额, 换手率%

# 批量查询
df = data.get_multi_kline(days=5)                   # 全市场
df = data.get_multi_kline(codes=["sh600519", "sz000001"], days=5)

# 透视表（行=代码，列=日期，值=收盘价）
pivot = data.get_pivot(days=5, field="收盘")

# 最新快照
snap = data.get_latest_snapshot()  # 全市场最新收盘价

# 日期范围查询
df = data.get_date_range_data("2024-01-01", "2024-06-30")
```

#### 股票列表

```python
stocks = data.get_stock_list(board="main")  # 仅沪深主板（000/001/002/003/600/601/603/605）
stocks = data.get_stock_list(board="all")   # 全 A 股（排除 ST/退市/北交所/科创板）
```

#### 缓存管理

```python
# 全量重建（从指定日期起）
data.rebuild(start_date="20100101")

# 回填更长历史
data.backfill()

# 强制重新读取磁盘
data.invalidate_cache()
```

#### 缓存结构

`cache/stock_kline_cache.parquet` 的列：

| 列名 | 类型 | 说明 |
|------|------|------|
| 代码 | str | `sh600519` / `sz000001` 格式 |
| 日期 | datetime64 | 交易日 |
| 开盘 | float64 | 开盘价 |
| 最高 | float64 | 最高价 |
| 最低 | float64 | 最低价 |
| 收盘 | float64 | 收盘价 |
| 前收 | float64 | 前一交易日收盘价；历史缺失时特征层用前一行收盘补足 |
| 成交量 | float64 | 成交股数（不是“手”） |
| 成交额 | float64 | 成交额（元） |
| 换手率% | float64 | 百分数口径，例如 `0.19` 表示 0.19% |

`cache/daily_basic_cache.parquet` 与 K 线事实表分开保存供应商量比、动态市盈率、
总市值和流通市值。这里的“供应商量比”是收盘快照值，适合展示和交叉校验；可复现
研究应优先使用特征层按历史成交量计算的量比。

#### 更新策略

- 每日管线优先用腾讯批量收盘快照更新当日全市场，只有历史缺口和落后标的才逐只修复
- 首次全量重建使用一次返回完整区间的新浪日线；每日历史修复由 akshare/腾讯主源完成，失败子集自动用 baostock 顺序回退
- 股票、ETF、指数和分钟缓存均采用临时文件 + 原子替换，避免进程中断留下半个 Parquet
- 腾讯历史源原始换手率是小数，适配层统一转换为百分数；腾讯快照成交量从“手”统一转换为“股”
- 日线缓存保留最近 60 个自然日（约 40 个交易日）

## 二、行业分类数据层 (`data/industry.py`)

### StockInfo 类

基于申万 2021 行业分类标准，提供个股 → 行业 1/2/3 级名称映射。

#### 基本使用

```python
from data.industry import StockInfo

info = StockInfo()

# 查询单只股票行业
info.get("sh600519")
# → {"申万1级": "食品饮料", "申万2级": "白酒Ⅱ", "申万3级": "白酒Ⅲ", "名称": "贵州茅台"}

# 列出所有一级行业
info.all_sectors(level=1)
# → ["农林牧渔", "基础化工", "钢铁", ...]

# 查看某行业所有股票
info.stocks_in_sector("电力设备", level=1)

# 与 DataFrame 合并
df_with_industry = info.merge(my_df, on="代码")
```

#### 行业分类体系

3 级分类结构：

```
1级（31 个）  →  2级（~130 个）  →  3级（389 个）
食品饮料      →  白酒Ⅱ          →  白酒Ⅲ
电力设备      →  电池            →  锂电池
医药生物      →  医疗器械        →  医疗设备
```

#### 数据构建

```python
# 首次构建（下载 Excel + 合并 spot 列表）
info.build()

# 强制重建
info.build(force=True)
```

数据流：

```
申万官网 StockClassifyUse_stock.xls
    ↓ (个股→6位行业代码)
SW2021_MAP (内置对照表)
    ↓ (6位代码→1/2/3级名称)
akshare 实时行情列表
    ↓ (代码+名称+状态过滤)
cache/stock_info.parquet
```

#### 代码转换

```
600519 → sh600519  (沪市主板)
000001 → sz000001  (深市主板)
920045 → bj920045  (北交所，系统已排除)
```

## 三、分钟数据层 (`data/minute.py`)

分钟缓存以 `代码 + 时间` 唯一标识每根 1 分钟 K 线。腾讯最近五日分时是主源，新浪分钟 K 线是网络异常时的备源；接口只覆盖近期数据，因此历史范围依靠每日增量更新逐步积累。

更新时只处理目标交易日实际有日线记录的股票和 ETF。每完成 1000 只就原子落盘一次；任务被系统终止后，下一次会自动跳过已完整覆盖到 14:55 的标的并从断点继续。

```python
from data.minute import MinuteData

minute = MinuteData()
minute.get_minute("sh600519")                # 最近一个缓存交易日
minute.get_minute("sz000001", "2026-08-24") # 指定股票和日期
minute.get_history("sh600519", days=6)        # 最近 6 个交易日，供盘中量比使用
minute.dates_of("sh600519")                  # 可查询的交易日
```

交互式查看器直接按代码过滤读取该 Parquet，不会先加载全市场完整分钟线：

```bash
python -m scripts.serve start minute
# http://127.0.0.1:8765/minute_view.html
```

页面支持名称/代码搜索、交易日切换，以及悬停查看对应分钟的价格、涨跌幅、OHLC、VWAP、成交量、成交额和 5 日同分钟盘中量比。

## 四、ETF / 指数 / 源适配 / 存储 / 补齐

### ETF（`data/etf.py`）

独立缓存 `cache/etf_kline_cache.parquet`。代码多为纯数字（如 `510050`），OHLC/成交额格式与股票日 K 兼容，可选股 `--universe etf`。

```python
from data.etf import ETFData
etf = ETFData()
etf.update()
etf.get_kline("510050", days=10)
```

### 指数（`data/index.py`）

`cache/index_kline_cache.parquet`，默认覆盖上证指数 `sh000001`、深证成指 `sz399001`、沪深300 `sh000300` 等。主源与股票一致（腾讯）；全挂时可用 ETF 代理兜底（需在展示侧标注）。

```python
from data.index import IndexData
IndexData().update()
```

### 源适配（`data/sources.py`）

把 AkShare/腾讯/BaoStock 等外部字段映射为 `schema` 契约（成交量统一为股、换手率为百分数等）。BaoStock 线程不安全，失败回退时须顺序调用。

### 原子存储（`data/storage.py`）

`atomic_write_parquet` / `atomic_write_json`：同目录临时文件 + `os.replace`，避免中断损坏正式缓存。日线/ETF/指数/分钟更新均走此路径。

### 字段补齐（`data/enrichment.py`）

每日管线 `enrich` 阶段：把分钟增量成交量按日汇总，**只填日 K 空成交量，不覆盖供应商已有值**。

## 五、选股日记与市场资讯（SQLite）

### 选股日记（`data/journal.py`）

- 路径：`state/stock_journal.sqlite3`（备份在 `state/backups/`）
- 只存案例与追加式决策事件；日 K 仍读 Parquet，查看时动态叠加标记
- 服务入口：`python -m scripts.serve start journal` → http://127.0.0.1:8765/stock_journal.html
- 细节见 [19-选股日记](19-选股日记.md)

### 市场资讯（`data/market_news.py`）

- 路径：`state/market_news.sqlite3`
- 缓存同花顺公开重要资讯的标题/摘要/时间/链接，以及用户的影响记录；支持 `as_of` 防剧透
- 每日更新含非关键 `news` 阶段；失败不阻断行情更新
- 服务入口：`python -m scripts.serve start news` → http://127.0.0.1:8765/market_news.html
- 细节见 [20-市场资讯复盘](20-市场资讯复盘.md)


### 训练闭环与交易事实辅助

- `state/training_sessions.sqlite3`（`data/training_sessions.py`）：T+1 训练日计划 / 决策快照 / 心态 / 复盘；见 [14-T+1交易训练](14-T+1交易训练.md)
- `cache/trading_calendar.parquet`（`data/calendar.py`）：交易日缓存；缺失时退回工作日近似，半日市用内置列表（收盘 11:30）
- `cache/daily_limit_facts.parquet` / `cache/stock_status.parquet`（`data/stock_facts.py`）：日 K 推导涨跌停与 ST 状态；可选东财涨停池补充
- 每日更新非关键阶段 `stock_facts` 刷新日历与涨跌停事实

## 六、每日统一更新与质量门禁

推荐只使用统一入口：

```bash
python -m scripts.update_cache
python -m scripts.update_cache --validate-only
python -m scripts.update_cache --only minute,enrich,validate --target-date 2026-08-27
```

完整流程为 `股票日线 → ETF → 指数 → 分钟 → enrich → validate → news → market_context → stock_facts → reports`（见 `pipeline.daily_update.STAGES`）。`enrich` 阶段把分钟增量成交量按日汇总，只补日 K 空值、不覆盖原始数据。质量门禁除日期覆盖外，还会检查目标日股票/ETF 成交量覆盖率。运行期间每个阶段都会更新 `cache/daily_update_status.json`；关键数据未达到覆盖要求时命令返回非零退出码，并跳过报告刷新。

同一时间只允许一个更新进程持有 `cache/.daily_update.lock`，避免手工补跑与系统定时任务同时写缓存。

## 七、数据关系

```
stock_info.parquet（代码、名称、申万行业）
├── 1:N → stock_kline_cache.parquet（日 K 事实）
├── 1:N → daily_basic_cache.parquet（估值/市值/供应商量比）
├── 1:N → minute_kline_cache.parquet（1 分钟 K）
├── 并行 → etf_kline_cache.parquet / index_kline_cache.parquet
└── 特征 → cache/features/<池>-<profile>/（由 features/ 计算，非 data/ 写入）

state/stock_journal.sqlite3     # 日记案例与事件（按代码关联行情）
state/market_news.sqlite3       # 资讯缓存与影响记录
state/training_sessions.sqlite3 # T+1 训练闭环
cache/trading_calendar.parquet  # 交易日历
cache/daily_limit_facts.parquet # 涨跌停事实
```

上层通过 `StockData` / `ETFData` / `MinuteData` 等读行情，通过 `StockInfo.merge()` 补行业；特征计算见 [16-指标与特征体系](16-指标与特征体系.md)。
