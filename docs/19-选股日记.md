# 选股日记

选股日记用于把“看到了什么”、“为什么准备进出”和“后来结果如何”串成可复查的决策链。它不额外维护一份日K数据，而是在查看时动态读取现有 Parquet 行情，再把 SQLite 中的日记标记叠加到K线上。

## 启动和入口

```bash
# 单独确保选股日记所在的共享服务已启动
python -m scripts.serve start journal

# 或一键启动所有 Web 入口
python -m scripts.serve
```

浏览器打开 <http://127.0.0.1:8765/stock_journal.html>。选股仪表盘的K线弹窗、分时查询页和 T+1 交易训练页都有日记入口，会自动带入当前证券代码。

## 建议工作流

1. 输入6位代码或名称，打开该标的日K。
   鼠标悬停任意蜡烛时，提示框会额外显示“该蜡烛开盘价 → 最新交易日收盘价”的区间价差、区间涨跌幅和K线数量，方便直接判断从当时介入并持有至今的结果。
   点击日K蜡烛后，页面会先把该交易日和收盘价同步到日记表单，再在日K下方展开对应分时图，方便一边对照日K、分时，一边写原因。内嵌分时默认显示全日；点击“动态分时”后从开盘逐分钟回放，横轴始终固定为全天，尚未播放的价格不会显示。播放期间“当时价格”会跟随最新可见分钟同步，因此可以按当时真正看得到的信息记录心理状态和决策；行情日期仍保持为所选交易日。本地没有该日分钟缓存时会原地提示，但已经同步的日记日期和价格不会丢失；需要更大视图时可点“完整分时页”。
2. 新建一个“研究案例”。同一只股票的不同观察周期应建立不同案例，避免新旧逻辑混在一起。
3. 在K线上选择行情日，记录观望、进场计划、实际进场、持有、离场计划、实际离场、失效或复查。
4. 理由只写当时可见的证据；把触发条件、失效条件、目标价、止损价、仓位和复查日期分开填写。
5. 复盘时新增“复查”或“更正”事件，不改写历史。时间线同时保留行情日和实际记录时间，可用来识别事后归因。
6. 如果日期或案例选错，点击该条记录右上角的“删除”。它会进入当前案例的回收站，不再出现于K线和时间线；案例状态会按剩余的最后一条记录自动回退。误删可从回收站恢复。

## 案例状态

| 事件 | 事件后的案例状态 | 含义 |
|---|---|---|
| 观望 | 观望中 | 逻辑尚未形成可执行计划 |
| 进场计划 | 计划中 | 已定义触发和失效条件 |
| 实际进场 / 持有 | 持有中 | 已进场或决定继续持有 |
| 离场计划 | 待离场 | 已有可执行的离场条件 |
| 实际离场 | 已结束 | 本次观察周期结束 |
| 逻辑失效 | 已失效 | 原研究假设已不成立 |
| 复查 / 更正 | 状态不变 | 追加评估或更正，但不覆盖旧结论 |

## 数据存储与备份

- 日K：继续使用 `cache/stock_kline_cache.parquet` 和 `cache/etf_kline_cache.parquet`，无需额外复制。
- 日记：`state/stock_journal.sqlite3`，只保存案例和决策事件。
- 备份：页面的“备份日记”会生成一致性副本到 `state/backups/`。

`state/*.sqlite3` 和备份目录默认不提交 Git，因为这是个人数据，不是代码产物。请定期将备份文件复制到 Time Machine 或其他安全位置。

## 当前版本边界

- 日记是个人本地工作台，没有登录和多用户权限。
- 日记事件不直接改写；普通观点变化应追加“更正”。只有记错日期或案例时才建议移入回收站，数据库仍保留原文以便恢复。
- 它用于决策训练和复盘，不会自动下单，也不把日记当作策略有效性证明。
