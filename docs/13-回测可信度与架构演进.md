# 13 — 回测可信度与架构演进

## 一、这次优化解决了什么

量化系统最危险的问题，不是策略暂时不赚钱，而是研究结果看起来很好，却无法说明
“当时能否知道、能否下单、按什么价格成交、资金曲线如何计算”。本轮先改造通用资金
模拟层，目标是让结果具备正确性、可复现性和可审计性。

### 1. 每日权益按收盘价盯市

旧逻辑用买入价计算持仓市值。持仓期间即使股票大跌，权益曲线也保持不变，直到卖出
当天才一次性体现亏损，会系统性低估回撤和波动。

现在统一使用：

```text
当日权益 = 可用现金 + Σ(持仓股数 × 当日收盘价)
```

若股票当日停牌或行情缺失，使用最近一个可得价格；只有没有任何历史价格时才退回
买入价。期末强平后，最后一个权益点会扣除卖出费用并把持仓归零。

### 2. 回测随机过程可复现

同日出现多个信号时，部分策略会随机打乱候选顺序。过去每次运行可能买入不同股票，
导致同一组参数产生不同结果。

通用引擎现在使用独立随机数生成器，默认 `random_seed=42`。策略通过 `ctx.rng` 排序，
不会再受进程内其他随机调用干扰。两个旧组合模拟也提供了 `--seed`。

### 3. 日 K 线内成交歧义显式化

只有日线时，若同一天最高价超过止盈价、最低价又跌破止损价，无法知道盘中哪一个先
发生。引擎现在必须采用明确政策：

| 参数 | 含义 | 适用场景 |
|---|---|---|
| `stop_first` | 先按止损成交 | 默认值，偏保守 |
| `target_first` | 先按止盈成交 | 乐观上界或敏感性分析 |

正式评估应至少同时运行两种口径。如果结论因此反转，说明日线粒度不足，应改用分钟线
或逐笔数据验证。

### 4. 费用口径可表达最低佣金

`compute_lots`、买入成本和卖出净额现在共用同一套费用函数。`min_commission` 表示单笔
最低佣金；默认仍为 `0`，用于兼容历史结果。准备模拟真实账户时，应填入自己的实际
券商费率与最低收费，而不是照搬示例值。

最低佣金不仅影响盈亏，还会影响“现金是否足够买一手”，所以必须在计算手数前纳入，
不能在回测结束后统一扣减。

### 5. 结果从 HTML 升级为结构化对象

`SimEngine.run(return_result=True)` 返回 `SimulationResult`，包含：

- 初始资金、期末权益、起止日期；
- 完整交易列表和逐日权益曲线；
- 随机种子、费用和成交顺序等回测假设；
- 总收益、年化收益、年化波动、Sharpe、最大回撤、Calmar、胜率、盈亏比等指标；
- 可用 `to_dict()` 转为 JSON 兼容字典。

示例：

```python
result = SimEngine(MyStrategy()).run(
    capital=100_000,
    start_date="2024-01-01",
    commission_rate=0.0001,
    stamp_tax=0.0005,
    min_commission=5,
    random_seed=42,
    intrabar_exit_policy="stop_first",
    return_result=True,
)

print(result.metrics.max_drawdown_pct)
print(result.metrics.sharpe_ratio)
print(result.assumptions)
```

HTML 报告同步显示最大回撤、Sharpe 和关键回测假设；交易明细不再把所有非止盈交易都
写成“尾盘”，而是区分止损、到期、策略退出和期末平仓。

### 6. 数据对象不再被策略扫描污染

过去引擎为了过滤主板，会直接替换 `StockData._cache`。一旦扫描抛异常或没有信号，
原始缓存不会恢复，后续模块可能只看到过滤后的数据。现在过滤发生在隔离的数据视图
中，传入的共享数据对象始终保持不变。

## 二、绩效指标的统一口径

| 指标 | 口径 | 使用提醒 |
|---|---|---|
| 总收益率 | `期末权益 / 初始资金 - 1` | 已包含配置的交易费用 |
| 年化收益率 | 按 252 个交易日复利折算 | 样本很短时会被夸大 |
| 年化波动率 | 日收益标准差 × `sqrt(252)` | 依赖正确盯市的权益曲线 |
| Sharpe | 日均收益 / 日收益标准差 × `sqrt(252)` | 当前无风险利率按 0 处理 |
| 最大回撤 | 权益相对历史峰值的最大跌幅 | 比单纯胜率更能说明资金风险 |
| Calmar | 年化收益 / 最大回撤 | 回撤为 0 时不计算 |
| 盈亏比 | 总盈利 / 总亏损绝对值 | 没有亏损样本时不强行写无穷大 |

不要单独按一个指标选策略。短样本的高 Sharpe、少数交易形成的高胜率、极端参数得到
的高年化收益，都不能直接作为实盘依据。

## 三、研究到实盘的五层门禁

### 第 1 层：数据门禁

- 交易日覆盖、代码覆盖率、重复行、空值和 OHLC 合法性；
- 前复权/后复权口径统一，除权除息日单独核对；
- 分钟线必须检查午休、重复时间和缺失分钟；
- 每次研究记录数据截止日，避免结果与后来补入的数据混淆。

### 第 2 层：信号门禁

每个字段都要标明“事件发生时间、数据可用时间、策略决策时间”。信号日收盘后才能
确认的数据，不得用信号日收盘前的价格成交。统计研究中使用未来最高/最低价的模块，
只能解释为机会空间分析，不能称为可执行收益。

### 第 3 层：撮合门禁

- 明确 T+0/T+1、最小交易单位、涨跌停和停牌；
- 明确订单类型、成交等待、撤单、滑点和部分成交；
- 日线同时触发止盈止损时做上下界测试；
- 小额高频策略必须启用实际最低佣金。

### 第 4 层：验证门禁

参数选择只能使用训练区间；验证区间和最终测试区间必须按时间顺序隔离。推荐采用：

```text
训练窗口 → 选择参数 → 下一段验证 → 窗口向前滚动 → 汇总样本外结果
```

同时对参数邻域做稳定性检查。只有一个尖锐参数点赚钱，周围全部亏损，通常是过拟合
而不是稳定规律。

项目现在提供统一的 `backtest/validation.py`：时间留出支持可配置隔离期，滚动前推
同时支持固定训练窗口和锚定扩张窗口，并检查乱序、重复、重叠与样本不足。网格优化器
已接入时间留出；参数排名和同分破局只读取训练指标，验证收益不会再参与选优。

### 第 5 层：上线门禁

先跑影子账户，记录策略信号、理论订单、实际可成交价和偏差原因；再用极小资金灰度。
设置单日亏损、最大回撤、最大持仓、异常数据和接口故障的熔断条件。实盘表现必须与
回测使用同一指标口径比较。

## 四、当前仍然存在的边界

本轮没有把以下问题伪装成已经解决：

1. 策略 07～14 已迁移到 `RebalanceEngine`，但旧版文档收益需要在统一口径下重跑，
   不能继续沿用为当前结论。
2. 执行模型已支持滑点、最低佣金、成交额容量和一字涨跌停拒单；日线仍无法还原
   盘口排队顺序，容量也只是按成交额比例近似。
3. 当前股票池不是严格的历史时点成分股，仍可能存在幸存者偏差。
4. `backtest/engine.py` 中使用未来最高价/最低价的模块属于统计研究，不是可执行回测。
5. 通用资金模拟尚未统一基准曲线、行业暴露、风格暴露和容量分析。
6. 通用 walk-forward 切分器已经建立，但网格优化命令目前仍是单次留出，其他策略也
   尚未接入多折训练、选参和样本外结果聚合。

## 五、下一阶段的推荐顺序

1. 建立 point-in-time 股票池与退市标的归档，控制幸存者偏差；
2. 在统一切分器上建立所有策略共用的多折研究器与参数稳定性热力图；
3. 增加基准收益、超额收益、Beta、行业/风格暴露和换手容量；
4. 用分钟线复核日线中一字板、成交容量和收盘执行假设；
5. 最后再接模拟盘事件流，核对“信号 → 委托 → 成交 → 持仓 → 归因”全链路。

这套顺序的原则是：先保证结果没有明显计算错误，再保证可以复现和审计，然后提高
撮合真实性，最后才扩大策略和自动交易规模。
