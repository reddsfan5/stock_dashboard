# 04 — 回测系统

## 架构

```
backtest/
├── engine.py   # 统计回测引擎：11 个策略 + 滑动窗口 + 统计分析
├── proverbs.py # 市场口诀：七项事件定义、指数对照与聚类区间
├── proverb_report.py # 市场口诀独立报告渲染
├── slow_rise.py # 缓涨N日：次日开盘买入、T+1止盈与5日退出
├── slow_rise_report.py # 缓涨策略对比和逐笔审计报告
├── grid.py     # 网格交易回测：2 个策略 + 日内分钟线
├── execution.py # 统一费用、滑点、整手、容量和涨跌停执行模型
├── rebalance.py # 周期轮动：前一日信号、逐日盯市、调仓审计
├── validation.py # 时间留出、隔离期与滚动前推切分
├── trading_trainer.py # 无未来数据的 T+1 手动训练状态机
├── sim_engine.py # 策略无关的资金模拟与撮合主循环
├── sim_core.py # 费用、手数、逐日盯市、期末平仓等公共规则
├── sim_types.py # 交易、持仓、权益、结构化结果
└── metrics.py  # 统一绩效指标
```

四类研究定位不同：`engine.py` 回答“这个条件历史上是否有统计优势”，`proverbs.py`
回答“口语经验在固定定义下是否优于条件基线”，`grid.py`
回答“这笔钱按分钟网格规则运行会怎样”，`sim_engine.py` 回答“有限资金按策略逐日交易后，
账户净值与风险会怎样”，`rebalance.py` 专门处理策略 07～14 这类周期换仓组合。

市场口诀前七项使用独立事件研究报告，因为旧统计表无法同时表达 1/3/5 日收益、
指数超额、条件基线和按信号日聚类的置信区间。运行方式和本次结果见
[17-市场口诀回测](17-市场口诀回测.md)。

“低位连续小涨会有大涨”的进一步可执行验证使用 `slow_rise.py`：它先要求信号日收盘
位于近30日价格区间下方30%，再模拟次日开盘成交、T+1、5%止盈、第五日尾盘退出、
费用与滑点。报告同时保留无低位过滤的控制组，结果和复现方式见
[18-缓涨止盈策略回测](18-缓涨止盈策略回测.md)。

资金受限的策略模拟统一走 `SimEngine`。它按当日收盘价计算持仓市值，固定随机种子，
记录退出原因，并可返回 `SimulationResult`。完整可信度口径见
[13-回测可信度与架构演进](13-回测可信度与架构演进.md)。

周期轮动引擎通过接口强制执行“前一交易日形成信号，下一交易日成交”，并对每一个
交易日记录权益。`ExecutionConfig` 可配置最低佣金、滑点、价格步长、成交额参与率和
一字涨跌停拒单；所有成交或拒单都会进入 `SimulationResult.events`。

时间序列验证统一使用 `validation.py`。`chronological_holdout()` 负责训练/隔离/验证
三段式留出，`walk_forward_splits()` 支持固定长度滚动窗口和锚定扩张窗口；切分器会拒绝
乱序、重复、区间重叠和训练样本不足，防止各脚本自行切片时悄悄引入时间泄漏。

# 第一部分：统计回测引擎 (`backtest/engine.py`)

## 设计模式

```
StatsConfig（参数配置）
    ↓
WindowStats（模板方法基类）
    ├── _condition_matrix()  → 是否满足条件 (子类实现)
    ├── _calculate_outcome() → 收益计算 (子类实现)
    └── run()                → 滑动窗口遍历 (模板方法)
    ↓
StatsEngine（批量运行 + 汇总输出）
```

- **`StatsConfig`**：统一参数（连续天数、重叠阈值、目标收益、持有天数）
- **`DataPrepper`**：从缓存准备透视表（收盘价、最高、最低、日涨跌、K线重叠区%）
- **`WindowStats`**：抽象基类，子类只需实现两个方法，`run()` 是固定模板

## 回测流程

```
DataPrepper 准备数据
    │
    ▼
for 每只股票:
    for 每个交易日:
        if 连续 N 天满足条件:
            记录信号
            计算 N+1 买入 → N+M 卖出的收益
    │
    ▼
AnalysisResult（总样本、成功数、收益分布、多阈值统计）
```

## 策略详解

### 策略 1：连续重叠低买高卖 (`OverlapBuyStrategy`)

连续 N 天两日 K 线重叠区 > X%（默认 3%），说明价格企稳窄幅震荡。

```
条件: overlap_pct > X% 连续 N 天
买入: day[N+1].low （信号确认后次日最低价买入）
卖出: day[N+2].high（再次日最高价卖出）
收益: (sell - buy) / buy × 100%
```

### 策略 2：连续上涨追涨 (`RisingStreakStrategy`)

连续 N 天上涨后，次日是否继续涨。

```
条件: close > prev_close 连续 N 天
买入: day[N].close（N天收盘确认信号后追入）
卖出: day[N+1].close（次日收盘）
收益: (次日收 - 当日收) / 当日收 × 100%
```

### 策略 3：连续上涨创新高 (`RisingNewHighStrategy`)

连涨后未来 M 天能否创出新高，衡量追涨后的上行空间。

```
条件: close > prev_close 连续 N 天
参考: day[N].high
目标: 未来 horizon 天 max(high)
收益: (峰顶 - 参考高) / 参考高 × 100%
```

### 策略 4：连续重叠收盘买入 (`OverlapCloseStrategy`)

与策略 1 类似，但买入时机改为第 N+1 天收盘价——更贴近实际（收盘时执行）。

```
条件: overlap_pct > X% 连续 N 天
买入: day[N+1].close（收盘确认后买入）
卖出: day[N+2].high
```

### 策略 5：基准策略 (`BaselineStrategy`)

**无任何条件**，每天都对所有股票做"低买次高卖"，作为其余策略的**收益基准线**。如果某个策略跑不过基准，说明该条件信号反而有害。

```
条件: 无条件（永远 True）
买入: day[i].low
卖出: day[i+1].high
样本量: 最大（所有股票 × 所有天）
```

### 策略 6：放量/缩量上涨 (`VolumeUpStrategy`)

```
条件: close > prev_close AND 成交额日增/日减
买入: day[N-1].close
卖出: day[N].close
```

- `volume_increase=True`：放量上涨 → 主力资金推动
- `volume_increase=False`：缩量上涨 → 惜售、筹码锁定

### 策略 7：地量突破 (`VolumeDryUpStrategy`)

成交量缩至极低水平 → 变盘在即。

```
条件: vol < avg_vol(N天) × vol_ratio（默认 50%）
买入: day[i].close
卖出: 未来 horizon 天 max(high)
收益: (峰顶 - 收盘) / 收盘 × 100%
```

### 策略 8：跳空缺口回补 (`GapFillStrategy`)

```
条件: day[i].low > day[i-1].high（向上跳空）
回补: 未来 horizon 天 min(low) < gap_day_low
结果: 统计补缺概率（非收益）
```

### 策略 9：超跌反弹 (`OversoldBounceStrategy`)

```
条件: close < prev_close 连续 N 天
买入: day[N+1].low
卖出: day[N+2].high
```

### 策略 10：布林带收敛突破 (`BollingerSqueezeStrategy`)

布林带宽度缩至近期均值 70% 以下 → 大行情爆发前兆。

```
条件: BB_width < 过去N天BB_width均值 × 0.7
      BB_width = (2×σ) / MA
买入: day[i].close
卖出: 未来 horizon 天 max(high)
```

### 策略 11：多信号叠加 (`MultiSignalStrategy`)

K线重叠 > 3% **AND** 缩量（成交额日减），双重确认。

```
条件: overlap_pct > X% AND vol < prev_vol
买入: day[N+1].low
卖出: day[N+2].high
```

# 第二部分：网格交易回测 (`backtest/grid.py`)

基于单只股票的**日内分钟级 K 线**，模拟网格交易。设计模式完善：

| 模式 | 位置 | 说明 |
|------|------|------|
| Strategy | `AbstractGridStrategy` | 两种网格策略可互换 |
| Template Method | `AbstractGridStrategy.run()` | 公共回测流程在基类 |
| Builder | `GridConfig` | 链式构建网格参数 |
| Value Object | `Bar`, `Trade`, `Position` | 不可变数据对象 |

## 公共概念

### 网格配置 (GridConfig)

```python
config = (GridConfig(base_price=10.0)
    .with_step(StepMode.PCT, 0.5)    # 每格 0.5%
    .with_levels(5)                    # 上下各 5 层
    .with_lot(100)                     # 每笔 100 股
    .with_price_range(8.0, 12.0)      # 有效区间
    .with_position_limits(0, 1500))   # 持仓 0~1500 股
```

| 参数 | 说明 |
|------|------|
| `step_mode` | `PCT`(百分比) 或 `DIFF`(固定差价) |
| `grid_step` | 每格步长 |
| `grid_levels` | 上下各 N 层 |
| `lot_shares` | 每笔基础股数 |
| `multiplier_levels` | 特定层倍数 `{3: 2}` = 第3层下2倍 |
| `price_floor/ceiling` | 有效价格区间 |
| `cage_to_market` | 超笼子转市价 or 废单 |

### 费率

```python
FeePolicy(commission=0.00025,    # 佣金 万2.5
          min_commission=5.0,    # 最低5元
          stamp_tax=0.0005)      # 印花税 万5（仅卖出）
```

### 回测流程（模板方法）

```
initialize → for bar in bars → check_triggers → execute → close_out
```

## 模式 1：成交驱动型网格

### 核心逻辑

按照银河证券公开说明，启动后以基准价和涨跌比例计算相邻买卖价，同时提交
买、卖两笔限价委托。一侧全部成交后，撤销另一侧委托，以成交价更新基准，
再计算并提交新的一对委托，循环至收盘。

```
基准价 P
  ├─ 预埋买单 P × (1-step)，冻结对应现金
  └─ 预埋卖单 P × (1+step)，冻结对应证券

任一侧全部成交 → 撤销反向单 → 成交价成为新基准 → 重新双挂
```

### 适用场景

成交效率优先、希望减少滑点的场景。代价是预埋单会占用资金和证券。

## 模式 2：到价触发型网格

### 核心逻辑

启动后只监控基准价上下的条件价，价格到达条件后才提交委托。未触价时不
提前占用资金或证券；报出尚未成交的限价单会冻结对应资券。

```
基准价 P
  ├─ 监控买入条件 P × (1-step)
  └─ 监控卖出条件 P × (1+step)

到价 → 可选跟踪最低/最高价 → 反弹/回落满足条件 → 才提交委托
     → 按“触发委托后”或“全部成交后”更新时间点更新基准
```

### 到价触发型参数语义

- **累计反弹**：价格先跌破买入网格，随后持续记录最低价；从最低价向上反弹
  到设定比例或差价时才触发买入。
- **累计回落**：价格先突破卖出网格，随后持续记录最高价；从最高价向下回落
  到设定比例或差价时才触发卖出。
- **保底价触发**：仅在累计反弹/回落已开启时生效。反转过程中若先回到原网格
  价，则不再等待更差的反弹/回落目标，直接在原网格价触发。
- **触发价格**：普通模式是对应买卖网格；启用累计反弹/回落后，是极值计算出的
  反转目标或保底网格价。页面会动态画出该触发线。
- **委托价格**：支持对手价近似、触发价限价和排队限价。分钟数据没有买一卖一，
  “对手价”通过滑点近似；排队限价从下一分钟起用 OHLC 判断是否全部成交。
- **更新时间点设置**：可在触发委托后立即更新，或等待委托全部成交后更新。后者
  能避免未成交却移动基准，但未成交委托会暂停新一轮监控。
- **更新基准价**：可选对应网格价、实际触发价或实际成交价；触发后立即更新时
  尚无成交价，因此不能选择成交价。
- **自动撤单**：只对排队限价有效，超过设置的完整分钟数仍未成交则撤单并释放
  冻结资券。
- **倍数委托**：分钟监控点一次跨过多格时，按跨格数放大委托数量，并受买卖最大
  倍数限制；新基准更新到对应的跨格网格价。
- **次日基准价更新**：可保留收盘时基准，也可把下一交易日基准更新为当日收盘价。
  单日回放只展示计算结果，不虚构下一交易日成交。
- **监控行情**：默认使用分钟 OHLC 路径代理盘中最新价，也可只用分钟收盘价。
  两者都不是券商实时 Level-1 逐笔监控。

累计反弹/回落与保底价的定义依据券商条件单公开说明中的共同规则；银河特有的
基准价更新时间点与更新价格选项，以银河 APP 参数页和公开使用记录交叉核对。
本项目实现的是可解释的分钟级仿真，不声称复刻银河柜台私有撮合细节。

### 适用场景

重视资金和证券使用效率的场景。代价是触价后才报单，快速行情中可能滑点或
无法成交。

## 两种网格对比

规则依据：中国银河证券官网的智能交易业务介绍，以及中国证券报对银河证券相关
负责人的模式说明：

- https://www.chinastock.com.cn/newsite/cgs-services/stockBroker/smartTrading.html
- https://www.cs.com.cn/qs/202510/t20251024_6519092.html

| | 成交驱动型 | 到价触发型 |
|---|---|---|
| 委托时机 | 启动及每次成交后双侧预埋 | 到达条件价后报单 |
| 资券占用 | 预先冻结买单现金和卖单证券 | 未触价不占用 |
| 成交价格 | 限价成交，模拟不计滑点 | 触价后成交，模拟计入滑点 |
| 一侧成交后 | 撤销反向单、更新基准并双挂 | 更新基准并监控新条件 |
| 主要取舍 | 成交效率优先 | 资券效率优先 |

## 日内动态回放

`backtest/intraday_grid.py` 提供独立的相邻网格模拟核心，供分时服务的
`grid_simulator.html` 页面调用。它不会替代上面的历史回测模式，定位是帮助观察
一个交易日内价格、网格锚点、成交和账户状态如何逐分钟演化。

```bash
python -m scripts.serve start grid
```

浏览器打开：

```text
http://127.0.0.1:8765/grid_simulator.html
```

页面可切换成交驱动型与到价触发型，并按照银河创建页设置：

- 初始基准价，留空时使用当日开盘价；
- 按比例或固定差价计算网格，上涨和下跌可合并或分开设置；
- 买入和卖出委托数量可合并或分开设置；
- 有效价格上下限、保留底仓和最大持仓；
- 买卖委托倍数、超价格笼子转市价、盘后更新基准价和策略有效期；
- 到价型累计反弹、累计回落、保底价触发、委托价格、基准价更新时间点与更新价；
- 到价型排队限价、自动撤单、监控行情方式和跳格倍数委托；
- 初始现金与持仓、佣金、卖出税费和到价型滑点。

动态显示：

- 当前锚点、下一买入价和下一卖出价；
- 每分钟价格、网格线及买卖成交点，右侧同步显示相对昨日收盘价的涨跌幅；
- 现金、持仓、可用资券、冻结资券、账户净值和相对持有收益；
- 当现金不足、达到最大持仓或触及保留底仓时的未成交原因。

模拟器假设标的允许 T+0。分钟内采用阳线 `O→L→H→C`、阴线
`O→H→L→C` 的确定性路径近似触发顺序；成交驱动型按预埋限价成交，到价型
默认按触发价加滑点成交；排队限价从后续分钟起用 OHLC 判断整笔成交。它不自动
核验具体证券的交易制度，也不能从分钟 K 线还原盘口排队、部分成交和真实分笔
顺序。

完整术语、两种模式的状态差异、参数设计方法，以及 520500 最近 10 日参数搜索
脚本见 [11-网格交易](11-网格交易.md)。

“超笼子废单转市价”在分钟回放中使用分钟端点和设定的笼子比例近似，实盘
判定需要逐笔盘口。“盘后自动更新基准价”和“有效期”属于跨日条件单管理；
单日回放只计算下一交易日基准价，不生成所选交易日之后的虚构成交。
