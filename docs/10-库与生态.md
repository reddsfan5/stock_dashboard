# 10 — 库与生态

本文档记录项目的依赖技术栈，以及值得研究的量化库生态（2026-08 调研）。

## 一、当前技术栈

| 库 | 版本 | 用途 | 在项目中的角色 |
|---|------|------|----------------|
| akshare | >=1.18 | 唯一数据源 | 股票K线走腾讯接口（`stock_zh_a_spot_tx` / `stock_zh_a_hist_tx`），ETF 列表走东财（`fund_etf_spot_em`） |
| pandas | >=2.0 | 数据处理核心 | 缓存、指标、回测全部基于 DataFrame |
| numpy | >=1.26 | 数值计算 | 指标向量化计算 |
| pyarrow | >=14.0 | Parquet 缓存 | `stock_kline_cache.parquet`（约170MB）读写 |
| tqdm | >=4.60 | 进度条 | 拉数、回测进度显示 |
| pyyaml | >=6.0 | 配置 | `config/pipeline.yaml` |
| requests | — | HTTP | 仅 1 处直接调用 |

### 设计取舍

- **无 matplotlib/plotly** — 所有报表为纯 HTML+JS（K线图客户端渲染），自包含可离线
- **无外部回测框架** — `backtest/` 与 `sim_*.py` 全自研，T+1、涨跌停、手续费规则完全可控
- 极简栈的代价：策略迭代慢、缺少现成的绩效分析工具

## 二、值得研究的库

### 性价比最高的三个增量

| 库 | 是什么 | 对项目的价值 |
|---|--------|--------------|
| vectorbt | Numba 加速的向量化回测，秒级跑数千参数组合 | 参数扫描试错，替代逐个 subprocess 跑策略的低效方式。缺点：撮合不真实（按 bar 价成交），适合粗筛，精验仍用自研 sim 引擎 |
| TA-Lib | C 实现的 150+ 技术指标 | `backtest/indicators.py` 目前自写 MA/动量等，TA-Lib 性能更好、指标更全，可对照验证 |
| quantstats / pyfolio-reloaded | 绩效分析（夏普、回撤、alpha/beta、收益曲线） | 策略报告目前只有胜率和盈亏，可补机构级绩效指标 |

vectorbt 参数扫描示例（对比现有 `run_all_strategies.py` 逐策略 subprocess 的方式）：

```python
import vectorbt as vbt
import pandas as pd

close = pd.read_parquet("cache/stock_kline_cache.parquet").pivot(
    index="日期", columns="代码", values="收盘")

fast, slow = vbt.MA.run_combs(close, [5, 10, 20], [20, 30, 60])
entries = fast.ma_crossed_above(slow)
pf = vbt.Portfolio.from_signals(close, entries, freq="1D")
pf.total_return()  # 一次跑完 3×3 组参数的全市场收益
```

quantstats 一行生成绩效页（可放进现有 output/ 报告体系）：

```python
import quantstats as qs
qs.reports.html(returns, output="output/quant_report.html")
```

### 数据源补充（akshare 挂掉时的备胎）

| 库 | 特点 | 接入点 |
|---|------|--------|
| baostock | 免费无需注册，历史数据全（1990年起），比腾讯接口稳定 | `scripts/update_cache.py` 的 `get_stock_list` 失败时降级 |
| tushare | 积分制，强在财务/基本面数据 | 申万行业分类目前靠 Excel，tushare 有接口化数据 |
| efinance | 东财轻量接口，比 akshare 快 | 高频小请求场景 |
| AKTools | akshare 的 HTTP API 封装 | 配合局域网服务架构，直接给手机端用 |

2026-08-15 的教训：腾讯接口 SSL 抖动导致整条链路失败，加 30s 重试后恢复。**双数据源才是根本解法**。

### 回测框架（研究借鉴，不建议替换自研）

| 框架 | 状态（2026） | 借鉴点 |
|------|--------------|--------|
| backtrader | 经典但 EOL（2023 起长期维护模式） | 社区资料最丰富，适合学回测概念 |

## 四、落地状态（2026-08-16）

### 1. baostock 双数据源（核心升级）

- 新增 [data/sources.py](../data/sources.py)：akshare 主源 + baostock 备源，统一输出格式
  （成交额单位统一为**万元**，与缓存/选股阈值一致；baostock 返回元，×1e-4 换算，
  经 demo_sources 三源实测验证比率 10000）
- [data/kline.py](../data/kline.py) `update()/rebuild()/backfill()` 支持 `fetch_fn`/`threads`
  参数注入数据源；失败代码记录在 `self.last_failed`（空数据=成功，与真失败区分）
- [scripts/update_cache.py](../scripts/update_cache.py)：
  - `--source akshare|baostock|auto`（默认 auto=akshare 主源，失败子集自动 baostock 回退）
  - `--limit N` 测试用；launchd 定时任务无参调用不受影响
- baostock 为全局单 socket 会话（不线程安全），回退 pass 顺序执行（threads=1）
- **待办**：ETF 数据的 baostock 回退（baostock 对 ETF K 线支持未验证）；baostock 在 py3.9 上
  依赖已有重试逻辑，全市场回退一遍约 6-10 分钟（顺序拉取）

### 2. quantstats 绩效报告

- [scripts/strategy_08_etf_momentum.py](../scripts/strategy_08_etf_momentum.py) 自动导出
  `output/etf_momentum_trades.csv` / `output/etf_momentum_equity.csv`
- [scripts/quant_report.py](../scripts/quant_report.py)：任意权益/交易 CSV → 机构级绩效页
  （Sharpe/Sortino/CAGR/最大回撤/月度热力图），基准用本地 ETF（离线，不走 yfinance）
  ```bash
  python scripts/quant_report.py --equity output/etf_momentum_equity.csv --trades output/etf_momentum_trades.csv
  ```
- 注意：ETF 缓存目前只有 2024-01 起数据（`data/etf.py` 默认 start 20240101），
  策略 8 实际回测区间为 2024-02~今。要补齐 2022 起历史：`python data/etf.py --start 20220101`

### 3. vectorbt 参数扫描

- [scripts/sweep.py](../scripts/sweep.py)：均线金叉全组合粗筛（ETF 池/主板股票），
  输出 `output/sweep_results.csv` + 可选热力图
- **必须用 .venv 运行**：py3.9 下 vectorbt 0.26 锁 numba<0.57→numpy<1.24，与系统
  numpy 2.0 冲突，已隔离在项目 `.venv`（--system-site-packages 共享项目依赖）
  ```bash
  .venv/bin/python scripts/sweep.py --universe etf --fast 5,10,20 --slow 20,30,60
  ```
- 首轮结论：ETF 池 MA5/MA60 金叉 +59%（与策略 8 动量结论互证）；股票全市场裸金叉
  深亏（与策略 3/11 的"均线金叉失效"结论一致）——粗筛定位的典型用法

### 5. run_all_strategies 并行化（2026-08-16 追加）

- [scripts/run_all_strategies.py](../scripts/run_all_strategies.py) 改为多进程并行：
  14 个策略独立 subprocess，默认并发 min(8, CPU核, 策略数)，每进程 ~3GB 内存
  （本机 64GB 内存 8 并发无压力）；`--workers N` 调并发、`--only 08,13` 只跑指定
- 各策略完整输出落 `output/logs/*.log`，终端只打一行结果，跑完自动刷新导航页
- 墙钟时间从"串行求和"降为"最慢策略 + 启动开销"

### 踩坑记录（py3.9 + 2026 生态）

| 坑 | 解法 |
|----|------|
| vectorbt 0.26 在 py<3.10 锁 numba<0.57，与 numpy 2.0 不兼容 | .venv 隔离（numpy 1.23.5 + numba 0.56.4） |
| 新版 plotly 移除 heatmapgl，vectorbt 主题模板崩溃 | venv 内锁 plotly==5.13.1 |
| talib-binary 已从 PyPI 下架 | brew update 修复 macOS 26 兼容后 brew install ta-lib |
| quantstats 0.0.7x 硬依赖 IPython 但未声明 | 显式安装 IPython |
| talib 0.7 只收 1-D numpy 数组；ROCP 返回小数（老版本返回百分数） | 逐列 to_numpy；×100 对齐 |
| efinance 东财接口连接重置（与腾讯同款抖动） | demo 内重试+跳过，不影响主链路 |
