# 服务管理

项目当前有 **2 个 HTTP 服务和 2 个计划任务**。分时、网格、T+1 训练、选股日记与
市场资讯并不是五个独立服务器，而是共享行情缓存、搜索索引和 API 的五个业务入口。

此外还有一个由 Codex 按需启动的本地 STDIO MCP `stock-data`。它不监听端口、不常驻、
不加入 `scripts.serve`，因此不计入下表运行单元。详见
[25-本地股票研究MCP](25-本地股票研究MCP.md)。

| 运行单元 | 默认地址 | 职责 | 是否常驻 |
|---|---|---|---|
| 交互 Web | `127.0.0.1:8765` | 分时查询、T+0 网格回放、T+1 交易训练、选股日记、市场资讯及其 API | 是 |
| 静态报告 | `127.0.0.1:8000` | 兼容原有索引和静态 HTML 报告 | 是 |
| 每日更新 | 工作日 18:30 | 全量 `update_cache`（报告/交互页刷新，结束后 `--lan` 重启 web+reports） | 否，按计划运行 |
| 周六轻量 | 周六 07:00 | 仅 `update_cache --only market_context`（补抓周五美股收盘后的海外宽基） | 否，按计划运行 |

## 一键启动与查看状态

所有命令都从项目根目录执行：

```bash
# 一键启动两个 HTTP 服务；不会触发耗时的数据更新
python -m scripts.serve

# 等价写法
python -m scripts.serve start all

# 查看两个服务和每日更新任务的真实状态
python -m scripts.serve status
```

日志位于 `output/logs/interactive_web.log` 和
`output/logs/static_reports.log`。进程记录位于 `cache/services/`，它们属于运行时
状态，不提交 Git。

## 按功能单独启动

```bash
python -m scripts.serve start minute
python -m scripts.serve start grid
python -m scripts.serve start trainer
python -m scripts.serve start journal
python -m scripts.serve start news
python -m scripts.serve start web
python -m scripts.serve start reports
```

前五条会分别给出对应页面地址，但底层都会启动同一个 `web` 进程。这是有意的：
它们共用同一份行情和搜索索引，拆成多个进程只会重复占用内存，并增加端口与版本不一致的
概率。

业务入口如下：

- 分时查询：<http://127.0.0.1:8765/minute_view.html>
- 网格回放：<http://127.0.0.1:8765/grid_simulator.html>
- T+1 训练：<http://127.0.0.1:8765/trading_trainer.html>
- 选股日记：<http://127.0.0.1:8765/stock_journal.html>
- 市场资讯：<http://127.0.0.1:8765/market_news.html>
- 静态导航：<http://127.0.0.1:8000/index.html>

## 停止、重启与端口冲突

```bash
python -m scripts.serve stop web
python -m scripts.serve restart web
python -m scripts.serve stop all
```

统一入口默认只停止由它自己启动的进程。若 8765 被本项目的历史服务占用，状态会显示
“旧/错误服务占用”，可运行：

```bash
python -m scripts.serve restart web --replace-conflicts
```

该参数会先核对进程命令和工作目录，只替换本项目已知的旧服务；如果端口属于无关程序，
命令会拒绝终止它。8000 若显示“launchd/外部管理”，普通 `stop reports` 不会卸载外部
LaunchAgent，避免管理权混乱。

## 数据更新不是常驻服务

计划任务不包含在 `start all` 中。手动执行或诊断：

```bash
# 工作日全量（与 LaunchAgent 一致；门禁通过后刷新报告/交互页，并 restart --lan）
python -m scripts.update_cache

# 仅校验缓存新鲜度
python -m scripts.update_cache --validate-only

# 周六轻量：只刷新市场情境 / 海外宽基（道指、纳指、标普等）
python -m scripts.update_cache --only market_context
```

macOS LaunchAgent（仓库副本在 `scripts/launchd/`，安装到 `~/Library/LaunchAgents/`）：

| Label | 时刻 | 命令 |
|---|---|---|
| `com.stock.cache-update` | 工作日 18:30 | `update_cache`（含报告/交互页刷新 + 服务重启） |
| `com.stock.market-context-saturday` | 周六 07:00 | `update_cache --only market_context` |

工作日全量更新在 reports 阶段会额外刷新交互页 shell、板块图谱与每日操盘清单（`scripts.reports.refresh_apps`）；管线结束后默认以 `--lan` 执行 `python -m scripts.serve restart all --replace-conflicts`，把 web+reports 拉到局域网可访问（可用环境变量 `STOCK_SERVE_LAN=0` 关闭）。服务重启失败只记日志，不把已成功的数据更新判为失败。

任务结束后 `serve status` 显示「已调度」是正常状态，不代表定时任务失效。日志：

- 全量：`~/Library/Logs/stock_update.log`
- 周六轻量：`~/Library/Logs/stock_market_context_saturday.log`

重新加载示例：

```bash
UID=$(id -u)
launchctl bootout gui/$UID/com.stock.market-context-saturday 2>/dev/null || true
cp scripts/launchd/com.stock.market-context-saturday.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.stock.market-context-saturday.plist
```

## 开发模式

需要临时端口或希望前台查看请求日志时，可以直接运行底层服务：

```bash
python -m scripts.services.minute_viewer --serve --port 8877
```

日常使用推荐统一入口，避免再次出现旧静态服务器与新版 API 服务同时占用 8765 的情况。
